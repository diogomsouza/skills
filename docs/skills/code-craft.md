# code-craft

Code Craft leads complex or long-running implementation work when delegation, independent verification, or resumable execution materially helps. The lead agent owns scope, architecture, integration, and acceptance while implementing work itself and assigning bounded tasks to other agents when useful.

It establishes a runtime goal, a specification, and a progress ledger. Work advances through phases with explicit outcomes and verification selected before implementation. The workflow integrates changes, resolves findings, and records accepted phases in local Git commits when applicable. A design document is created only when new shared technical decisions need a separate record.

Use it for changes spanning components, work with difficult integration or recovery behavior, or tasks that need continuity across sessions. Straightforward edits normally do not need this workflow unless it is explicitly requested. It requires runtime goals, subagents, and access to the models and roles selected for the work.

The result is an implemented and verified change with a record of completed work, evidence, and any unresolved limitations.
